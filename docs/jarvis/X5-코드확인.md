## 1. 먼저 말 걸기 — 일부

**세션이 켜져 있을 때(CLI 가 붙어 있을 때): 된다.**

- 허브는 받은 말을 DB 에 저장하고, 곧바로 CLI 에 넘깁니다. 앱이 열려 있는지와 상관없습니다.
  - 받는 곳: `hub/src/web/routes/messages.ts:121-153`
  - 저장: `hub/src/sync/messageService.ts:884-889`
  - CLI 로 전달: `hub/src/sync/messageService.ts:908-927`
- 에이전트 답도 허브 DB 에 저장되므로, 나중에 앱을 열면 보입니다(`hub/src/socket/handlers/cli/sessionHandlers.ts:155`, `:240-250`).
- 답이 끝나면 CLI 가 `ready` 사건을 보내고(`cli/src/api/apiSession.ts:1087-1101`), 허브가 이걸 보고 알림을 보냅니다(`hub/src/notifications/notificationHub.ts:68-74`).

**세션이 꺼져 있을 때(비활성·보관): 안 된다.**

- 받는 곳이 `requireActive: true` 라서(`hub/src/web/routes/messages.ts:127`) **409 `session_inactive`** 로 거절합니다(`hub/src/web/routes/guards.ts:29-34`).
- 줄 세워 두지도, 알아서 깨우지도 않습니다.
- 그래서 먼저 `POST /api/sessions/:id/resume` (보관된 세션이면 `/reopen`)을 불러야 합니다.
  - `hub/src/web/routes/sessions.ts:207-248`, `:250-284`
  - 응답의 `sessionId` 를 써야 합니다(247행). 새 ID 가 올 수 있습니다.
- resume 은 그 머신의 runner(에이전트를 띄우는 상주 프로그램)가 켜져 있어야 됩니다. 아니면 503 `no_machine_online` 입니다(`hub/src/sync/syncEngine.ts:2941-2948`).
- 참고: 앱은 409 를 받으면 한 번 자동으로 resume 하고 다시 보냅니다(`android/app/src/main/kotlin/app/hapi/companion/feature/chat/ChatViewModel.kt` 의 `isSessionInactive`). 크론은 이걸 직접 해야 합니다.

**인증**

- `POST /api/auth` 에 `{accessToken: <CLI_API_TOKEN>[:namespace]}` 를 보내면 JWT(로그인 표)를 줍니다(`hub/src/web/routes/auth.ts:29-37`).
- JWT 는 **4시간 뒤 만료**됩니다(`hub/src/web/routes/auth.ts:63-67`). 크론은 4시간마다 새로 받아야 합니다.

**예약 메시지: 된다(조건 있음).**

- `scheduledAt`(밀리초) 은 지금부터 **7일 안**이어야 하고, `localId` 가 꼭 있어야 합니다. 첨부·`steer` 와 같이 쓸 수 없습니다(`shared/src/apiTypes.ts:529-546`).
- 허브가 5초마다 때가 된 메시지를 CLI 로 보냅니다(`hub/src/sync/syncEngine.ts:237`, `:952`, `hub/src/sync/messageService.ts:1044-1085`).
- 예약을 **걸 때도** 세션이 켜져 있어야 합니다(같은 409 검사).
- 추론: 걸어 둔 예약은 세션이 꺼져도 DB 에 남고, CLI 가 다시 붙으면 보내집니다(`hub/src/sync/messageService.ts:978-999`).

**모름**: Claude 가 **로컬(터미널) 모드**일 때 바깥에서 넣은 말이 어떻게 처리되는지는 확인하지 못했습니다.

## 2. 모델 없이 고정 문구 — 안 된다

- REST 로 넣은 말은 **항상 `role: 'user'`(사용자 말)** 로 저장되고 에이전트에게 갑니다(`hub/src/sync/messageService.ts:871-882`). 주현님 짐작이 맞습니다.
- `meta.sentFrom` 은 늘 `'webapp'` 으로 고정입니다(`hub/src/web/routes/messages.ts:148`).
- 「대화창에만 남는 공지」나 「푸시만 보내기」 같은 REST 길은 없습니다.
  - 푸시 쪽 REST 는 구독·기기 등록뿐입니다(`hub/src/web/routes/push.ts:21-43`, `hub/src/web/routes/devices.ts:51`, `:76`).
  - `shared/src/schemas.ts` 에도 공지(notice) 같은 메시지 종류가 없습니다.
- 대화창에 회색 한 줄로 뜨는 **사건(event) 메시지**는 있습니다(`role:'agent'`, `content.type:'event'`). 다만 CLI 만 `/cli` 소켓으로 보냅니다(`cli/src/api/apiSession.ts:1087-1128`).
- 추론(공식 길 아님): CLI 토큰으로 `/cli` 소켓에 직접 붙어 사건 메시지를 보내면, 허브는 내용을 따지지 않고 저장·방송합니다(`hub/src/socket/handlers/cli/sessionHandlers.ts:125-155`). 형식을 잘못 보내면 에이전트에게 말로 들어갈 수 있어 위험합니다.
- `/api/work-graph/events` 는 별도 장부에 적기만 하고, 대화창·푸시로 나가지 않습니다(`hub/src/web/routes/workGraph.ts:29-63`).
- → 「엔진 변경 필요」 목록에 적었습니다(`CHANGES.md`).

## 3. 바깥에서 넣은 말 구별 — 일부

- 보내는 쪽이 정할 수 있는 칸: `text`, `localId`, `attachments`, `scheduledAt`, `deliveryMode`. **`meta` 는 못 정합니다.**
- `localId` 검사는 「빈 글자 아님」뿐입니다(`shared/src/apiTypes.ts:531`). 접두어(예: `cron-…`)를 붙일 수 있습니다.
- `localId` 는 허브 SQLite `messages.local_id` 에 남습니다(`hub/src/store/index.ts:441-454`). 같은 `localId` 로 다시 보내면 새로 안 넣습니다(`hub/src/sync/messageService.ts:892-898`). 재시도에 안전합니다.
- **Claude 전사(JSONL)에는 안 남습니다.** CLI 는 `localId` 를 줄 관리에만 쓰고, Claude 에는 글(+첨부 경로)만 넘깁니다(`cli/src/claude/runClaude.ts:386-391`, `cli/src/claude/claudeRemoteLauncher.ts:464-473`).
- **Codex** 에는 `clientUserMessageId` 로 넘어갑니다(`cli/src/codex/codexRemoteLauncher.ts:4213-4222`). Codex 기록 파일(rollout)에 실제로 적히는지는 Codex 프로그램 쪽 일이라 **모름**입니다.
- 결론: 모든 하네스 기록에 확실히 남기려면 **본문 글에 표식을 넣는 수밖에 없습니다.** 허브 DB 쪽 구별은 `localId` 접두어로 됩니다.

## 4. 업로드 — 된다

- 받는 곳: `POST /api/sessions/:id/upload`, 본문 `{filename, content(base64), mimeType}`. **세션이 켜져 있어야** 합니다(`hub/src/web/routes/sessions.ts:286-322`, `shared/src/apiTypes.ts:475-479`).
- **크기**: 파일 하나 **50MB**(`hub/src/web/routes/sessions.ts:38`, `cli/src/modules/common/attachmentLimits.ts:2`, 앱 `android/app/src/main/kotlin/app/hapi/companion/feature/chat/attachments/AttachmentPolicy.kt:19-36`).
- **종류**: 채팅 첨부는 제한이 없습니다. 앱은 사진·동영상 고르기, 아무 파일(`*/*`), 카메라 촬영을 씁니다(`android/app/src/main/kotlin/app/hapi/companion/feature/chat/ChatScreen.kt` 의 `PickMultipleVisualMedia`, `OpenMultipleDocuments`, `TakePicture`).
  - 4MB 넘는 사진은 긴 변 2048px, JPEG 품질 85로 줄여 올립니다(`AttachmentPolicy.kt:53-60`).
- **개수**: 허브·앱 모두 정해진 상한을 찾지 못했습니다(`shared/src/apiTypes.ts:532`).
- **떨어지는 곳**: 허브는 파일을 저장하지 않고 **에이전트가 도는 머신의 CLI** 로 넘깁니다(`hub/src/sync/rpcGateway.ts:353-355`).
  - CLI 머신의 `임시폴더/hapi-blobs/<세션ID>-XXXX/<시각>-<uuid>-<파일이름>` 에 본인만 읽을 수 있게(0600) 씁니다(`cli/src/modules/common/handlers/uploads.ts:214-263`, `cli/src/constants/uploadPaths.ts:4`).
  - 메시지에는 그 절대 경로가 붙고, Claude 에는 `@경로` 로 들어갑니다(`cli/src/utils/attachmentFormatter.ts:7-29`).
  - 세션이 끝나면 지웁니다(`cli/src/api/apiSession.ts:1292`). **오래 둘 파일은 에이전트가 따로 옮겨야 합니다.**
- 참고: 스크래치리스트(임시 메모장) 첨부는 따로입니다. **허브** `~/.hapi/scratchlist-attachments` 에 저장되고, 한도는 파일당 10MB·항목당 4개입니다(`shared/src/scratchlistAttachments.ts:22-35`, `hub/src/scratchlistAttachments/storage.ts:29-33`).

## 덤: `hapicompanion://bind` 딥링크를 adb 로 보냈는데 확인 카드가 안 뜸 — 원인 (고치지 않음)

증상(A36, 2026-10-09): `adb shell am start` 로 bind 링크를 보내면 연결 첫 화면(「직접 입력」 버튼이 있는 화면)에 머물고 「이 허브와 연결할까요?」 확인 카드가 안 뜬다. 앱이 떠 있을 때와 새로 뜰 때 모두 그렇다.

- 아래 줄 번호는 **태그 `v0.30.7` 기준**입니다. 이 브랜치의 `Navigation.kt` 는 집사 화면 때문에 줄이 밀렸습니다.
- 기기에서 재현해 보지는 못했습니다. 코드와 라이브러리 소스를 읽고 찾은 것입니다.
- 원인 후보가 둘이고, 화면 위쪽 안내 띠로 어느 쪽인지 가릴 수 있습니다.

### 원인 1 (코드 흐름상 확실, 기기 재현은 안 함) — 연결 화면이 이미 떠 있으면, 링크를 두 군데서 동시에 받아서 서로 지운다

앱이 아직 허브와 연결되지 않아 **연결 화면이 이미 화면에 있을 때** 생깁니다. 새로 뜰 때도 연결 안 된 앱은 첫 화면이 연결 화면이라 똑같습니다.

1. 링크가 오면 `MainActivity` 가 `pendingBindLink` 에 넣습니다.
   - 새로 뜰 때: `android/app/src/main/kotlin/app/hapi/companion/MainActivity.kt:68-75`
   - 떠 있을 때: `MainActivity.kt:97-101` → `:103-113`
2. 이걸 **두 곳**이 같은 순간에 받습니다.
   1. 바깥 내비게이션: `Navigation.kt:179-184`. 연결 화면으로 **뒤로 가기 기록을 전부 지우고 다시** 갑니다(`navigateClearingBackStack`, `:804-809` 의 `popUpTo(0) { inclusive = true }`).
   2. 지금 떠 있는 연결 첫 화면: `Navigation.kt:493-498`. 링크를 **자기 화면의 ViewModel(화면 상태를 들고 있는 객체)**에 넣고(`prefillFromLink`, `feature/pairing/PairingViewModel.kt:84-95`), `pendingBindLink` 를 비웁니다.
3. 순서: Compose 는 효과(LaunchedEffect)를 화면에 그린 순서대로 시작합니다. 바깥 쪽(1)이 먼저 돌아 연결 화면 묶음을 통째로 새로 만들고, 그다음 옛 화면(2)이 **곧 버려질 옛 ViewModel** 에 링크를 넣고 링크를 비웁니다.
   - 순서가 반대여도 결과는 같습니다. (2)가 먼저 링크를 비워도, (1)이 읽는 값(`collectAsState`)은 아직 바뀌기 전이라 그대로 이동합니다.
4. 새로 만든 연결 화면은 새 ViewModel 을 씁니다(`Navigation.kt:779`, 연결 묶음 항목마다 ViewModel 이 따로 있음). 확인 카드 내용(`prefill`)은 비어 있고, 링크도 이미 비워졌습니다. 그래서 카드가 안 뜹니다(카드는 `prefill != null` 일 때만, `feature/pairing/PairingScreen.kt:81`).
- 새로 뜰 때도 연결 첫 화면이 첫 프레임에 바로 그려집니다. navigation-compose 2.9.0 의 `NavHost` 가 그리는 도중에 그래프를 설정하고(`NavHost.kt:501`), 보이는 화면 목록을 StateFlow 의 현재 값으로 바로 읽기 때문입니다(`NavHost.kt:548`). 그래서 같은 경합이 생깁니다(추론: 라이브러리 소스 기준).
- 이미 연결된 앱이 세션 화면에 있을 때는 받는 곳이 하나뿐이라 카드가 정상으로 뜹니다.
- 고치는 방향(이번엔 안 함): 이미 연결 화면 묶음 안에 있으면 바깥에서 다시 이동하지 않거나, 링크를 받는 곳을 한 군데로 모읍니다. 앱 쪽 일이고 엔진 변경은 필요 없습니다.

### 원인 2 (README 예시를 그대로 썼다면 확실) — adb 명령에서 `&` 뒤가 잘려 `code` 가 빠진다

- `android/README.md:113-114` 의 예시처럼 보내면, PC 셸이 큰따옴표를 벗기고 `adb shell` 이 나머지를 **폰의 셸에 한 줄로 다시 넘깁니다.** 폰 셸은 따옴표 없는 `&` 를 「뒤에서 실행」 기호로 읽습니다.
  - 그래서 앱에는 `hapicompanion://bind?hub=...` 까지만 가고 `&code=...` 가 사라집니다.
- `code` 가 없으면 링크 해석이 실패합니다(`android/core/protocol/src/main/kotlin/app/hapi/protocol/pairing/BindLink.kt:48`).
- 그러면 앱은 확인 카드 대신 **위쪽 안내 띠**만 띄웁니다(`MainActivity.kt:109-112`, 표시는 `PairingScreen.kt:58`).
  - 띠 문구: 「연결 링크가 잘못되었거나, 불완전하거나, HTTPS를 사용하지 않습니다.」
- 바르게 보내는 법(폰 셸 안에서도 따옴표가 남게 감쌈):
  ```sh
  adb shell "am start -a android.intent.action.VIEW -d 'hapicompanion://bind?hub=https%3A%2F%2Fhub.example.com&code=<토큰>'"
  ```

### 어느 쪽인지 가리는 법

1. 위쪽에 위 안내 띠가 **떴다** → 원인 2 (명령의 따옴표 문제). 위처럼 다시 보내 보세요.
2. 띠 **없이** 첫 화면만 보인다 → 원인 1 (앱 안의 경합). 지금 코드로는 연결 안 된 앱에서 bind 링크로 카드를 띄울 수 없습니다. 앱 안의 「QR 스캔」이나 「직접 입력」으로 연결하세요(폰 기본 카메라로 QR 을 찍으면 같은 딥링크 경로라 똑같이 막힙니다).
3. 따옴표를 바로 잡은 명령으로도 카드가 안 뜨면 원인 1 입니다.
